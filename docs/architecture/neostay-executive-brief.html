01

The case in one page

Problem, answer, and where the project stands.

The problem. Neonatal units plan two things under uncertainty: how long each baby will stay, and how many skilled nurses each shift needs. Both are usually judged from experience, and neither leaves evidence behind when an establishment is questioned.

The answer. NeoStay turns a decade of the unit's own recorded outcomes into an expected length of stay with a realistic range, and turns the unit's own acuity policy into nurses per shift, the required skill mix, and a 24-hour roster that names any cot left without a qualified nurse. It runs in a web browser, behind sign-in, with no patient-level data.

Stated plainly. NeoStay is a decision-support prototype. It is not a medical device, it has not been clinically validated, and it never replaces clinical judgment. Every recommendation is advisory and requires a human decision.
02

What we want to prove, and how

The analytical plan in brief. Full detail in the dossier.

Table 1 — Four questions, four methods, one way to judge them
QuestionModels to be testedJudged by
How long will this baby stay? Survival models with competing risks (home, transfer, death); gradient boosting; quantile and Bayesian hierarchical variants Error in days and calibration, against today's method
What care level will this baby need next shift? Multi-state and ordinal models; cost-weighted gradient boosting Accuracy, with under-calling penalised
What will the unit need over the next fortnight? Seasonal time-series and state-space models; queueing approximation; simulation Error in nurse-hours, and whether the stated range holds
Who should take which cot tonight? Constraint-based optimisation, with today's rule as fallback Uncovered cots and planner acceptance
The rule we have set ourselves. A new model replaces the current method only if it is better on data it has never seen, stays calibrated, can be explained to the clinical lead, and runs fast enough to use at handover. Otherwise the simpler method stays. Everything is reported to the TRIPOD+AI standard, with performance published per birth-weight band and per branch.

Rollout in three phases

Phase 1Pilot

Configure one unit's grades and ratios, run in parallel with the current method for four weeks, measure task time and acceptance.

Phase 2Evidence

Historical data under governance; build and validate models; silent prospective run; published validation report.

Phase 3Group

Branch-by-branch rollout by configuration, roster optimisation, dashboards, annual revalidation.

Decisions requested

  1. Approve the pilot in one neonatal unit, with parallel running for four weeks.
  2. Name a data owner and start the governance route for a pseudonymised historical extract.
  3. Confirm the nursing policy to configure: grade ladder, ratios, supervision rules.
  4. Choose the hosting model: hospital server, hospital cloud tenancy, or managed container platform.
  5. Agree the success measures in Table 1 of the dossier, so adoption is decided on evidence.
What the hospital gets, whatever the models show. Even before any model is fitted, the unit gains a consistent way to classify acuity, a defensible figure for nurses per shift and skill mix, a record of shifts where cover was short, and a shared reference for its own policy. The modelling work adds accuracy and foresight on top of that.
